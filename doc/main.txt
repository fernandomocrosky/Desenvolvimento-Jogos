main.cpp - Como a implementação foi feita
==========================================

Arquivo: app/main.cpp
Script de build: build.sh

Objetivo: um programa pequeno, linkado à biblioteca do projeto, que gera
um dungeon, carrega na matriz (TileMap) e exporta para CSV, para depois
abrir no Excel.

1. A biblioteca (build.sh)
   - Não há CMake/make no ambiente, então o build é feito por um script
     com g++ e ar, em três passos:
       a) cada source/*.cpp é compilado separadamente em um .o
          (g++ -c), em build/obj/;
       b) os .o são reunidos numa biblioteca ESTÁTICA: build/libgame.a
          (ar rcs). Ela contém Vector2D, Transform2D, Collision2D,
          RigidBody2D, Dungeon2D e TileMap;
       c) app/main.cpp é compilado e LINKADO à biblioteca com
          -Lbuild -lgame (o linker procura "libgame.a" em build/).
   - O programa só inclui os headers (-Isource). As implementações vêm
     da biblioteca, não dos .cpp diretamente.
   - Para compilar: ./build.sh

2. O programa (app/main.cpp)
   Uso: ./build/dungeon_export [largura] [altura] [seed] [arquivo.csv]
   Padrões: 60 40 42 dungeon.csv

   Passos, cada um usando uma função da biblioteca:
     1) Dungeon2D dungeon(largura, altura); dungeon.generate(seed);
        -> gera a árvore BSP e os corredores;
     2) TileMap map; map.loadFromDungeon(dungeon);
        -> rasteriza o dungeon na matriz de tiles;
     3) map.saveCSV(caminho);
        -> exporta com a função de CSV da biblioteca (o retorno é
           [[nodiscard]], então é verificado);
     4) check.loadCSV(caminho);
        -> lê o arquivo de volta para confirmar que ele é válido.
   No final, imprime o mapa no terminal ('#' = parede, '.' = vazio) e um
   resumo: tamanho, seed, número de corredores e de células.

   - Os argumentos são validados (números inteiros, tamanho > 0). Em caso
     de erro, mostra o "usage" e sai com código 2.
   - Exceções da biblioteca (por exemplo, dungeon menor que 7 x 7) são
     capturadas, a mensagem é mostrada e o programa sai com código 1.

3. Arquivo gerado
   - output/dungeon.csv: 60 x 40, seed 42. Comando usado:
       ./build/dungeon_export 60 40 42 output/dungeon.csv
   - 1 = parede (WALL_TILE), 0 = vazio (EMPTY_TILE).

4. Abrindo no Excel
   - ATENÇÃO: no Excel em português, o separador padrão de CSV é ";", não
     ",". Se der dois cliques no arquivo, tudo fica na coluna A. O
     contrato exige vírgula, então o arquivo não foi alterado; a
     importação é que precisa indicar o separador:
       Dados > Obter Dados > De Arquivo > De Texto/CSV > escolher o
       arquivo > Delimitador: Vírgula > Carregar.
   - Para "ver" o dungeon: selecionar todas as células, deixar as colunas
     estreitas (largura ~2) e usar Formatação Condicional > Realçar
     Regras das Células > É igual a... 1 com preenchimento escuro.
